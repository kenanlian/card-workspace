The current guides describe **Card Workspace 1.3.4**. This release adds local image previews to Markdown cards, alongside the existing text excerpts and task progress.

## Right-side thumbnails by default

Cards use the first supported local image embedded in the note body. **Right thumbnail** is enabled by default, with **Crop to fill**. New installations and upgrades without a saved image preference use these defaults; explicitly saved choices are preserved.

Open **Settings → Card Workspace → Card images** to choose **Below title** or **Off**. The right thumbnail is 88 × 88 CSS pixels; the below-title image is 160 CSS pixels high and spans the card body. **Image fit → Show whole image** preserves the complete image instead of cropping it.

See [Card images](../guides/browsing-cards.md#card-images) for examples and [Settings](../reference/settings.md#card-images) for both new preferences. The settings tab now has nine options.

## Local images from the note body

Both Wiki embeds and Markdown images are supported, and attachments may be outside the folder being browsed. Supported formats are static PNG, JPEG, WebP, and BMP. Images appear on Markdown cards in folder, card-box, and linked-note sources. Clicking an image opens the card’s note.

Remote images, frontmatter cover fields, HTML images, embedded notes, SVG, AVIF, GIF, and animated PNG/WebP are excluded. Notes without a resolvable supported image reference keep their text layout. If the selected image fails validation or generation, another attachment is not tried.

## Stable loading and cached thumbnails

Cards reserve image space before loading once cached metadata identifies a supported reference within the file-size limit. Loaded images fade in over 240 ms, respecting reduced motion; later failures keep an unavailable placeholder of the same size. Multiple columns stay aligned by rows, with each card keeping its own height.

Images load only near the viewport. First-time thumbnail generation waits for visible text to load and a foreground paint; cached thumbnails are reused across restarts. Changing layout, fit, preview lines, or the search query does not regenerate them.

All image processing and caching remain local. See [Image limits and local caching](../reference/limits-and-privacy.md#image-limits-and-local-caching) for the original-image limits, cache budgets, and fallback behavior.
